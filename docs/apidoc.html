REST API for an online bookstore.

This API provides authentication, user management, book management, cart, favourites, orders, and other bookstore-related functionality.

auth

Authentication and account verification endpoints.

Includes:

  • User registration
  • User login
  • Email OTP verification
  • Resending OTP
  • Forgot password
  • Reset password

Register a new user

Creates a new user account using the provided personal information.

After successful registration, an OTP is generated and sent to the user's email address. The user must verify this OTP using the /auth/verifyOtp endpoint before the email address is considered verified.

This endpoint is publicly accessible and does not require authentication.

Registration flow

  1. Client submits the user's registration information.
  2. Server validates the registration data.
  3. A new user account is created.
  4. An OTP is generated and sent to the provided email address.
  5. The client uses /auth/verifyOtp to verify the email address.

required
integer

The user's 10-digit phone number.

required

Enum: "male" "female" "others"

Log in to an account

Authenticates an existing user using their email address and password.

If the credentials are valid, the server returns a JWT access token. The returned token can be supplied in the Authorization header when accessing protected API endpoints.

Authentication flow

  1. User submits their email address and password.
  2. Server validates the credentials.
  3. If valid, a JWT token is generated.
  4. The client stores the JWT token.
  5. The client sends the token with protected API requests.

Authorization header

Protected requests should include:

Authorization: Bearer <JWT_TOKEN>

This endpoint is publicly accessible and does not require an existing authentication token.

Request Body schema: application/json
required

Login credentials for an existing user account.

Email address associated with the user account.

Verify email OTP

Verifies the one-time password (OTP) that was sent to the user's email address during registration.

When the OTP is valid, the user's email address is marked as verified and a JWT access token is returned.

Verification flow

  1. User registers using /auth/register.
  2. Server sends an OTP to the registered email address.
  3. User submits the OTP and email address to this endpoint.
  4. Server validates the OTP.
  5. The user's email is marked as verified.
  6. A JWT access token is returned.

This endpoint is publicly accessible and does not require authentication.

Request Body schema: application/json
required

Email address and OTP received by the user.

otp
required
integer [ 100000 .. 999999 ]

Six-digit OTP sent to the user's email.

email
required
string <email>

Email address associated with the account.

Resend email verification OTP

Generates and sends a new one-time password (OTP) to the user's registered email address.

This endpoint can be used when the original OTP has expired, was not received, or is otherwise no longer usable.

The endpoint is publicly accessible and does not require authentication.

A user whose email address has already been verified cannot request another verification OTP.

Request password reset email

Requests a password reset email for a user account.

The current implementation requires a valid JWT bearer token. The email address is supplied in the request body and is used to identify the account for which the password reset process is started.

The authenticated user must also have a verified email address.

Authentication

This endpoint requires:

Authorization: Bearer <JWT_TOKEN>

Password reset flow

  1. Client authenticates using a JWT.
  2. Client submits the account email address.
  3. Server validates the JWT.
  4. Server checks whether the user's email is verified.
  5. Server sends a password reset email.
  6. The email contains a password reset token.
  7. The client uses the reset token with /auth/resetpassword/{token}.
Authorizations:
bearerAuth
Request Body schema: application/json
required

Email address associated with the account whose password needs to be reset.

email

string <email>

Reset user password

Changes the authenticated user's password using a password reset token.

The reset token is supplied as a path parameter and is expected to have been provided to the user through the password reset email.

The current implementation also requires a valid JWT bearer token.

Authentication

This endpoint requires:

Authorization: Bearer <JWT_TOKEN>

Reset password flow

  1. User requests a password reset.
  2. Server sends a reset email containing a reset token.
  3. Client extracts the reset token from the reset link.
  4. Client sends the reset token in the URL.
  5. Client sends the new password in the request body.
  6. Server validates the JWT and reset token.
  7. User's password is changed.
Authorizations:
bearerAuth
path Parameters
token
required
string
Example: eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.reset-token

Password reset token sent to the user's email address.

This token identifies and authorizes the password reset operation.

Request Body schema: application/json
required

The new password that should replace the user's existing password.

password
required
string <password> >= 8 characters

New password that replaces the existing password.

Responses

Get admin dashboard statistics

Retrieves aggregated key performance statistics for the administrator dashboard.

The dashboard aggregates:

  • Total revenue from non-cancelled orders
  • Total count of orders (all statuses)
  • Total books Ordered in system
  • Total sales and order count for the current month
  • Total sales and order count for the current year
  • Daily paid sales for the last 30 days
  • Best-selling book (by units sold and revenue)
  • Total registered users count
  • New users registered during the current month
  • User distribution by non-admin roles (user, seller, etc.)
  • Orders grouped by order status (paid, pending, cancelled, etc.)
  • Pending orders count
  • Books with low inventory (stock <= 10)

Rate limit: 30 requests per minute.

Get sales and revenue analytics

Retrieves aggregated sales metrics for non-cancelled orders grouped by day, week, or month.

Optional query parameters allow filtering by date range (startDate and endDate) and selecting the aggregation period (groupBy):

  • day: Groups data daily (YYYY-MM-DD) [default]
  • week: Groups data weekly (YYYY-Www)
  • month: Groups data monthly (YYYY-MM)

For each time bucket, the response returns:

  • totalRevenue: Sum of total prices
  • avgRevenue: Average order value
  • totalOrders: Count of orders
  • totalItems: Total quantity of books purchased

Rate limit: 30 requests per minute.

Authorizations:
bearerAuth
query Parameters
startDate
string <date>
Example: startDate=2026-01-01

Earliest order creation date to include (inclusive).

endDate
string <date>
Example: endDate=2026-10-01

Latest order creation date to include (inclusive).

groupBy
string
Default: "day"
Enum: "day" "week" "month"
Example: groupBy=day

Time-series bucket granularity.

Get month-by-month sales trends per category

Computes monthly sales quantities and revenue per category within a specified date range.

Validations enforced:

  • startDate and endDate are required valid date strings.
  • endDate must be strictly after startDate.
  • The date range between startDate and endDate cannot exceed 1 year.

Missing calendar months in the range are automatically densified with zero values.

Retrieve all books with search, sort, and pagination

Retrieves a paginated collection of active books from the catalog.

Supports keyword filtering by book title and author using case-insensitive regular expressions ($regex, $options: "i"). Results can be sorted in descending (newest) or ascending (oldest) chronological order by creation date.

Soft Deletion & Visibility

Soft-deleted books (isDeleted: true) are automatically excluded from the result set by a Mongoose pre(/^find/) query middleware.

Search & Filtering Capabilities

  • Title Search: Substring match against book titles.
  • Author Search: Substring match against author names.
  • Both filters can be used independently or combined.

Sorting Behavior

  • sort=new (default): Sorts descending by -createdAt (newest books first).
  • sort=old: Sorts ascending by createdAt (oldest books first).
  • Any unrecognized sort parameter defaults to new.

Pagination Rules

  • page: 1-based page index (defaults to 1).
  • limit: Number of records returned per page (defaults to 10).
  • Upper Bound: If limit exceeds 100, the server automatically caps it at 100.
  • Computes skip = (page - 1) * limit.
  • Computes totalPages = Math.ceil(totalItems / limit) and hasNextPage = page < totalPages.

Rate Limiting

  • Protected by getRateLimiter: Maximum 30 requests per minute per client IP.

Create a new book with cover image upload

Creates and registers a new book entity in the bookstore catalog.

This operation is restricted to verified administrators (role: 'admin'). The request must be transmitted as multipart/form-data to accommodate both book metadata fields and the binary image file for the book's cover.

Creation & Upload Flow

  1. Authentication: Caller provides a valid JWT Bearer token in the Authorization header.
  2. Authorization: restrictTo("admin") middleware verifies the caller holds admin role and that their email is verified.
  3. Rate Limiting: mutationLimiter restricts the caller to 10 mutations per minute.
  4. File Handling: Multer parses the multipart request, extracting the file from field coverImage and writing it to temporary disk storage (uploads/).
  5. Validation: validateBooks validates the presence and constraints of title, author, stock, description, price, and category.
  6. Cloudinary Upload: The server uploads the temporary cover image to Cloudinary under the "BookStore" folder.
  7. Cleanup: The local temporary file is deleted from disk using fs.unlink.
  8. Database Persistence: A new document is saved in MongoDB with the resulting Cloudinary HTTPS URL and initial defaults (totalSales: 0, ratingAverage: 0, ratingQuantity: 0, isDeleted: false).
  9. Response: Returns HTTP 201 Created with the complete book document.

Validation Rules

  • title: String, trimmed, non-empty, minimum length of 2 characters.
  • author: String, non-empty.
  • stock: Numeric, non-empty, non-negative integer.
  • description: String, non-empty.
  • price: Numeric, non-empty, non-negative, minimum length 1 character.
  • category: Must match one of the predefined categories: Fantasy, Action, Adventure, Mystery, Horror, Thriller, Romance, Self-help, Biography. Cannot be empty.
  • coverImage: Required binary file representing the book cover art.

Retrieve a book by its unique ID (with Redis caching)

Retrieves detailed information for a specific book identified by its unique MongoDB ObjectId.

High-Performance Redis Caching

This endpoint implements a cache-aside caching strategy using Redis:

  1. The server checks for the Redis key book:{bookId}.
  2. Cache Hit: If the key exists, cached JSON data is parsed and returned immediately without accessing the MongoDB database.
  3. Cache Miss:
    • Validates that bookId parameter is present and valid.
    • Queries MongoDB via Books.findById(bookId).
    • The Mongoose pre(/^find/) middleware automatically filters out soft-deleted books (isDeleted: false).
    • If the book is not found in MongoDB, returns HTTP 404 Not Found.
    • If found, writes the serialized book document into Redis under book:{bookId} and returns HTTP 200 OK.

Soft-delete a book from the catalog

Performs a soft deletion on the book specified by bookId.

This operation is restricted to verified administrators (role: 'admin').

Soft-Deletion Architecture

Rather than permanently purging the record from MongoDB, the controller updates the document with { isDeleted: true }:

  1. Preserves sales history, order relations, and aggregate analytics integrity.
  2. Mongoose pre(/^find/) middleware automatically intercepts all queries (find, findOne, findById) and applies { isDeleted: false }, ensuring deleted books are immediately hidden from the public store catalog.
  3. If the book does not exist or was already deleted, returns HTTP 404 Not Found.
