REST API for an online bookstore.

This API provides authentication, user management, book management, cart, favourites, orders, and other bookstore-related functionality.

auth

Authentication and account verification endpoints.

Includes:

  • User registration
  • User login
  • Email OTP verification
  • Resending OTP
  • Forgot password
  • Reset password

Register a new user

Creates a new user account using the provided personal information.

After successful registration, an OTP is generated and sent to the user's email address. The user must verify this OTP using the /auth/verifyOtp endpoint before the email address is considered verified.

This endpoint is publicly accessible and does not require authentication.

Registration flow

  1. Client submits the user's registration information.
  2. Server validates the registration data.
  3. A new user account is created.
  4. An OTP is generated and sent to the provided email address.
  5. The client uses /auth/verifyOtp to verify the email address.

Log in to an account

Authenticates an existing user using their email address and password.

If the credentials are valid, the server returns a JWT access token. The returned token can be supplied in the Authorization header when accessing protected API endpoints.

Authentication flow

  1. User submits their email address and password.
  2. Server validates the credentials.
  3. If valid, a JWT token is generated.
  4. The client stores the JWT token.
  5. The client sends the token with protected API requests.

Authorization header

Protected requests should include:

Authorization: Bearer <JWT_TOKEN>

This endpoint is publicly accessible and does not require an existing authentication token.

Request Body schema: application/json
required

Login credentials for an existing user account.

Verify email OTP

Verifies the one-time password (OTP) that was sent to the user's email address during registration.

When the OTP is valid, the user's email address is marked as verified and a JWT access token is returned.

Verification flow

  1. User registers using /auth/register.
  2. Server sends an OTP to the registered email address.
  3. User submits the OTP and email address to this endpoint.
  4. Server validates the OTP.
  5. The user's email is marked as verified.
  6. A JWT access token is returned.

This endpoint is publicly accessible and does not require authentication.

Request Body schema: application/json
required

Email address and OTP received by the user.

otp
required
integer [ 100000 .. 999999 ]

Six-digit OTP sent to the user's email.

email
required
string <email>

Email address associated with the account.

Resend email verification OTP

Generates and sends a new one-time password (OTP) to the user's registered email address.

This endpoint can be used when the original OTP has expired, was not received, or is otherwise no longer usable.

The endpoint is publicly accessible and does not require authentication.

A user whose email address has already been verified cannot request another verification OTP.

Request password reset email

Requests a password reset email for a user account.

The current implementation requires a valid JWT bearer token. The email address is supplied in the request body and is used to identify the account for which the password reset process is started.

The authenticated user must also have a verified email address.

Authentication

This endpoint requires:

Authorization: Bearer <JWT_TOKEN>

Password reset flow

  1. Client authenticates using a JWT.
  2. Client submits the account email address.
  3. Server validates the JWT.
  4. Server checks whether the user's email is verified.
  5. Server sends a password reset email.
  6. The email contains a password reset token.
  7. The client uses the reset token with /auth/resetpassword/{token}.
Authorizations:
bearerAuth
Request Body schema: application/json
required

Email address associated with the account whose password needs to be reset.

email
required
string <email>

Email address associated with the account.

Reset user password

Changes the authenticated user's password using a password reset token.

The reset token is supplied as a path parameter and is expected to have been provided to the user through the password reset email.

The current implementation also requires a valid JWT bearer token.

Authentication

This endpoint requires:

Authorization: Bearer <JWT_TOKEN>

Reset password flow

  1. User requests a password reset.
  2. Server sends a reset email containing a reset token.
  3. Client extracts the reset token from the reset link.
  4. Client sends the reset token in the URL.
  5. Client sends the new password in the request body.
  6. Server validates the JWT and reset token.
  7. User's password is changed.
Authorizations:
bearerAuth
path Parameters
token
required
string
Example: eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.reset-token

Password reset token sent to the user's email address.

This token identifies and authorizes the password reset operation.

Request Body schema: application/json
required

The new password that should replace the user's existing password.

password
required
string <password> >= 8 characters

New password that replaces the existing password.
